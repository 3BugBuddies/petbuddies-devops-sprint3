  1. 1O desenvolvedor clona o repositório e preenche o .env; o 00_preflight.sh confere sessão, providers e quota antes de criar qualquer recurso.
  2. 2O docker build --platform linux/amd64 gera a imagem do Oracle e a da API — o ACI executa somente amd64.
  3. 3O docker push envia as duas imagens ao Container Registry, criado por az acr create.
  4. 4A Azure CLI cria o grupo de recursos, o Key Vault e os dois Container Instances. Nenhum recurso é criado pelo portal.
  5. 5Cada Container Instance puxa sua imagem do Registry autenticando com a credencial guardada no cofre, que também injeta as senhas do banco.
  6. 6Na subida da API, o Flyway cria as 16 tabelas e a carga de demonstração no schema PETBUDDIES_CUIDADO.
  7. 7Tutor e veterinária consomem a API em HTTP na porta 8080; a persistência é evidenciada por SELECT direto no Oracle, na porta 1521.

Nenhum dado sensível existe em código: senhas, segredo JWT e credenciais do registry vivem no Key Vault e chegam aos containers como variáveis de ambiente protegidas. As imagens declaram usuário próprio — nenhum container roda como root.
